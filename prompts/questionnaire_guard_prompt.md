# [감시 프롬프트] 질문지 항목 추가 시 무결성 검증 가이드

이 프롬프트는 `script.js` 내에 **새로운 질문지 항목(문항)을 추가할 때**, 시스템의 모든 라이프사이클(렌더링 > 입력 > 등록 > 보기 > 수정)과 V2 다중 프로젝트 구조가 유기적으로 정상 동작하도록 보장하기 위한 체크리스트 및 감시 가이드입니다. 

향후 AI에게 새로운 항목 추가를 지시할 때, 이 프롬프트를 함께 참조하도록 하여 누락되는 로직이 없도록 통제하십시오.

---

## 🚨 필수 점검 체크리스트 (AI 작업 지침)

AI가 새로운 문항을 추가할 때 다음 5단계 로직이 완벽하게 호환되는지 점검하고 코드를 작성해야 합니다.

### 1. 데이터 모델 정의 (`script.js`의 `formData`)
- 새 항목 추가 시 반드시 고유한 영문 `id`를 부여해야 합니다.
- 기존에 정의된 `type`(`text`, `textarea`, `radio`, `checkbox`) 중 하나를 사용해야 렌더러가 정상 작동합니다.
- (선택) '기타' 텍스트 직접 입력이 필요한 경우 `allowDirectInput: true` 속성을 명시해야 합니다.

### 2. 동적 화면 렌더링 (`renderForm()`)
- `type`에 정의되지 않은 새로운 UI 요소(예: 파일 업로드, 달력 픽커 등)를 도입하는 경우, `renderForm()` 내의 HTML 생성 로직(switch/if문)에도 해당 `type`의 렌더링 코드를 반드시 추가해야 합니다.
- 공통 기능인 '확인중' 토글(`.tgl-checking`)이 디자인을 해치지 않고 정상적으로 부착되는지 확인합니다.

### 3. 데이터 추출 및 등록 (`submitForm()`)
- 항목이 추가되면 `submitForm()` 내의 값 추출 로직에 해당 항목이 정상적으로 잡히는지 확인해야 합니다.
- **[주의]** 새로운 `type`을 추가했다면, `submitForm()` 내부의 분기문(`if (item.type === '...')`)에도 해당 값을 DOM에서 읽어와 `data[item.id]`에 매핑하는 추출 로직을 필수로 구현해야 데이터 누락이 발생하지 않습니다.
- 추출 시 `.value.trim()` 처리를 통해 공백 데이터가 들어가지 않도록 방어 로직을 유지합니다.

### 4. 보기(Read-Only) / 수정(Edit) 모드 전환 (`updateModeUI()`)
- 보기 모드 진입 시 폼의 모든 요소가 `disabled` 처리되고 CSS(`.readonly-mode`)가 적용되는지 확인해야 합니다.
- 커스텀 UI(예: 슬라이더, 별점 등)를 새롭게 추가한 경우, `updateModeUI()` 내에 해당 커스텀 요소를 `disabled` 처리하는 로직을 별도로 추가해야 보기 모드에서 조작을 차단할 수 있습니다.

### 5. V2 백엔드 호환성 유지 (Reference: `v2_option_a_implementation_prompt.md`)
- 프론트엔드 통신 로직에는 `projectId`와 배포 환경 변수(`env`)가 동적으로 할당되어 있습니다. 
- 항목을 추가하는 과정에서 기존 `submitForm`의 `currentData.projectId = projectId;` 등의 병합 로직이나, `load.php` / `save.php`를 호출하는 `fetch` 라우팅 파라미터를 절대 훼손해서는 안 됩니다.

## 📌 적용 방법
새로운 설문 문항 추가나 수정을 AI에게 요청할 때, 프롬프트 말미에 다음 문구를 포함하세요.
> *"작업 시 반드시 `prompts/questionnaire_guard_prompt.md`의 [무결성 검증 가이드]를 참조하여, 문항 추가로 인해 데이터 추출(`submitForm`), 모드 전환(`updateModeUI`) 로직에 누락이 발생하지 않도록 조치해 줘."*
