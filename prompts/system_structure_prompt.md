# 프로젝트 구축 상세 질문지 시스템 구조 및 데이터 처리 로직

**목적:** 프로젝트 구축 상세 질문지 시스템의 동작 구조(질문지 추가 > 입력 > 등록 > 보기 > 수정) 및 물리적 데이터 처리 로직을 이해하고 이를 바탕으로 코드 분석 및 개선을 진행하기 위한 프롬프트 가이드입니다.

---

## 1. 시스템 동작 구조

### 1) 질문지 추가 (설계 및 화면 랜더링)
- **데이터 모델링 (`script.js`)**: 
  - `formData`라는 JavaScript 배열 객체를 통해 카테고리(category)와 각 문항 항목(items)을 정의합니다. 
  - 각 item은 `id`, `label`, `type`(text, radio, checkbox, textarea 등), `options` 등의 메타데이터를 가집니다.
- **동적 화면 생성 (`renderForm()` / `renderLandingPage()`)**: 
  - 페이지 로드 시 `formData`를 순회하며 HTML 폼 요소를 동적으로 생성하여 화면에 렌더링합니다.
  - 서버(DB)에서 기존 저장된 데이터가 있는지 API를 통해 확인(`load.php`)하며, 데이터가 존재하면 해당 값으로 폼을 프리필(Pre-fill)합니다.

### 2) 입력 (데이터 바인딩 및 사용자 상호작용)
- **입력 폼 컴포넌트**: text, radio, checkbox 요소로 구성되며 '기타(직접입력)' 항목 활성화 로직(`allowDirectInput`)을 포함합니다.
- **확인중 토글 (`.tgl-checking`)**: 
  - 고객사가 아직 확정하지 못한 항목에 대해 '확인중' 상태로 체크할 수 있는 토글 스위치가 존재합니다.
  - 이 토글이 활성화되면 해당 항목의 원래 입력 필드는 비활성화되고, 내부적인 값은 "확인중" 상태로 고정됩니다.

### 3) 등록 (데이터 수집 및 API 전송)
- **데이터 추출 (`submitForm()`)**:
  - `formData` 스키마를 기준으로 DOM에서 각 `id`에 매칭되는 입력값을 순회하며 추출합니다.
  - '확인중' 토글이 켜진 항목은 `[item.id]_checking = true` 플래그를 추가하고, 데이터 값을 "확인중"으로 강제 설정합니다.
  - `type`별 분기 처리: 
    - `radio`/`checkbox`: 선택된 value 추출. 만약 '기타'를 선택했다면 텍스트 박스의 입력값을 치환하여 최종 데이터에 저장합니다.
    - `text`/`textarea`: `.value.trim()`으로 데이터를 수집합니다.
- **API 통신 (`save.php`)**:
  - 수집된 최종 JSON 객체(`currentData`)에 식별자인 `projectId`와 `env`(환경 변수), `_is_test` 등의 메타데이터를 병합합니다.
  - `fetch` API를 사용하여 POST 메서드로 `${CONFIG.API_BASE_URL}/request_api/save.php` 엔드포인트에 전송합니다.
  - 응답 성공 시 사용자에게 완료 모달 팝업을 노출합니다.

### 4) 보기 (Read-Only 모드)
- **모드 전환 (`updateModeUI()` / View Mode)**: 
  - 데이터 제출이 완료되었거나, 이미 데이터가 등록된 URL로 접근 시 '보기 모드' 상태로 진입합니다.
  - 폼 내의 모든 요소(input, select, textarea 등)에 `disabled` 속성을 부여하여 입력을 차단합니다.
  - CSS 처리(`.readonly-mode` 등)를 통해 입력 필드의 테두리를 없애고 일반 텍스트 문서를 보는 것처럼 스타일을 변경합니다. 

### 5) 수정 (Edit 모드)
- **수정 상태 활성화**: 
  - 보기 모드에서 '수정하기' 버튼을 클릭하면 폼 요소들의 `disabled` 속성을 일괄 제거합니다.
  - 읽기 전용 CSS 클래스를 해제하여 다시 데이터를 입력하고 변경할 수 있는 상태(Edit Mode)로 UI를 전환합니다.
  - 수정이 완료된 후 등록 버튼을 누르면, 다시 [3) 등록] 단계의 `submitForm()` 프로세스를 동일하게 거쳐 `save.php` API로 기존 데이터를 덮어쓰기(Update) 합니다.

---

## 2. 물리적 데이터 처리 로직 요약

*   **Front-end 상태 관리**: `currentData`라는 전역 객체 변수를 통해 폼에 입력되는 상태값과 API 통신용 페이로드를 임시 보관하고 관리합니다.
*   **Back-end 연동 (PHP / API 통신)**:
    *   **조회 (`load.php?projectId={id}&env={env}`)**: GET 요청 방식. URL 파라미터에서 추출한 프로젝트 식별자 정보를 기반으로 DB(혹은 파일 시스템)에 저장된 기존 JSON 데이터를 불러옵니다.
    *   **저장/수정 (`save.php`)**: POST 요청 방식. Body에 JSON Payload를 담아 전달하며, 백엔드에서는 전달받은 식별자를 기준으로 Insert 또는 Update 작업을 수행합니다.
    *   **삭제 (`delete.php`)**: 특정 프로젝트나 항목 데이터를 삭제할 때 호출되는 API 엔드포인트입니다.
*   **식별자 구조**: 모든 데이터는 고유 식별자인 `projectId`를 기준으로 매핑 및 구분되며, 동일한 프로젝트라도 배포 환경(`TARGET_ENV`: 로컬/테스트/운영)에 따라 파라미터가 분리되어 처리됩니다.
